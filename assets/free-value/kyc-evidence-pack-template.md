# KYC / onboarding evidence pack: a template that arrives ready, not chased

Free to use, copy and share. No signup. Draft v0.1 by Moring AI (moring.ai). Illustrative structure, not a regulatory standard.

The idea: an agent gathers and compares evidence across systems and flags only true exceptions. A named reviewer decides, with the full record. The approval stays human.

## Case header
- Case ID, entity name, onboarding type, date opened
- Accountable owner: Head of KYC / Onboarding Ops (name)
- Assigned reviewer (name, role)

## 1. Evidence gathered (agent fills)
| Item | Source system | Retrieved at | Version / date of document | Status |
|---|---|---|---|---|
| Entity registration | | | | found / missing / stale |
| Ownership and control (beneficial owners) | | | | |
| Identity documents | | | | |
| Sanctions / PEP / adverse media screening | | | | clear / possible match |
| Address and contact verification | | | | |
| Prior relationship or case history | | | | |

## 2. Conflicts between systems (agent flags)
| Field | Value in system A | Value in system B | Which looks right and why | Needs human? |
|---|---|---|---|---|

## 3. Exceptions (sorted so the reviewer reads the real ones first)
| Type | Meaning | Who handles |
|---|---|---|
| True exception | A real risk or rule break | Reviewer decides |
| Data conflict | Two sources disagree | Reviewer or ops resolves |
| Missing document | Evidence not provided | Ops requests it |
| Stale evidence | Present but out of date | Ops refreshes |

## 4. Reviewer decision (human fills)
- Decision: approve / reject / request more
- Rationale (free text, required)
- Name, role, date and time
- Conditions or follow-ups

## 5. Audit link
- Link to the record of what the agent accessed and did (one queryable trail)

## How to use it
1. Pick one onboarding type and one team. Run the template by hand on 10 recent cases to see where evidence is scattered.
2. Count: systems touched, minutes spent reconciling, cases re-checked because the pack was thin. Keep these as your baseline (label them measured).
3. Only then decide what an agent should prepare. The reviewer's decision is never automated.
